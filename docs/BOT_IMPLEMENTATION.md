## 📋 Обзор

Реализован полностью функциональный Telegram бот с использованием aiogram 3.x.
Бот поддерживает регистрацию пользователей, выдачу заданий, обработку ответов,
отслеживание прогресса и управление уровнями сложности.

## 📦 Компоненты

### 1. FSM States (`bot/states.py`)

Определение состояний пользователя в FSM (Finite State Machine):

- **`idle`**: Начальное состояние, ожидание команды
- **`waiting_for_level`**: Ожидание выбора уровня сложности
- **`waiting_for_answer`**: Ожидание ответа на multiple choice задание
- **`waiting_for_text_answer`**: Ожидание текстового ответа (open question)
- **`waiting_for_level_change_confirm`**: Ожидание подтверждения смены уровня

#### Константы для callback_data

```python
CallbackData.LEVEL_BEGINNER       # "level:Beginner"
CallbackData.LEVEL_ELEMENTARY     # "level:Elementary"
CallbackData.LEVEL_ADVANCED       # "level:Advanced"
CallbackData.START_TASKS          # "start_tasks"
CallbackData.CONTINUE_TASKS       # "continue_tasks"
CallbackData.CHANGE_LEVEL_CONFIRM # "change_level:confirm"
CallbackData.CHANGE_LEVEL_CANCEL  # "change_level:cancel"
CallbackData.ANSWER_PREFIX        # "answer:"
```

### 2. Inline Keyboards (`bot/keyboards.py`)

Все inline клавиатуры вынесены в отдельный модуль:

- **`get_level_selection_keyboard()`**: Выбор уровня (Beginner/Elementary/Advanced)
- **`get_start_tasks_keyboard()`**: Кнопка "Начать первое задание"
- **`get_continue_tasks_keyboard()`**: Кнопка "Продолжить"
- **`get_answer_options_keyboard(options)`**: Варианты ответов (2 в ряд)
- **`get_level_change_confirm_keyboard()`**: Подтверждение смены уровня
- **`remove_keyboard()`**: Удаление клавиатуры

### 3. Middlewares (`bot/middlewares.py`)

Три middleware для обработки запросов:

#### LoggingMiddleware
- Логирование всех входящих сообщений и callback-запросов
- User ID, username, тип события, содержимое
- Время обработки запроса

#### StateLoggingMiddleware
- Логирование переходов между FSM состояниями
- Полезно для отладки user flow

#### ErrorHandlerMiddleware
- Обработка необработанных исключений
- Отправка дружелюбных сообщений пользователю
- Детальное логирование ошибок

### 4. Utils (`bot/utils.py`)

Вспомогательные функции для форматирования сообщений:

- **`get_day_name(day)`**: Название дня по номеру
- **`format_progress_message()`**: Форматирование прогресса
- **`format_statistics()`**: Форматирование статистики
- **`format_task_message()`**: Форматирование задания
- **`format_day_completion_message()`**: Сообщение о завершении дня
- **`format_theme_completion_message()`**: Сообщение о завершении темы

## 🎯 Handlers (Обработчики команд)

### 1. Start Handler (`bot/handlers/start.py`)

#### Команда `/start`

**Для новых пользователей:**
1. Показывает приветственное сообщение с описанием механики
2. Предлагает выбрать уровень сложности
3. Создает пользователя в БД
4. Загружает первую тему из Notion
5. Показывает кнопку "Начать первое задание"

**Для зарегистрированных пользователей:**
1. Приветствует пользователя
2. Показывает текущий прогресс
3. Проверяет выполнение дневного лимита
4. Предлагает продолжить или показывает сообщение о завершении дня

#### Callback handlers:
- **`process_level_selection`**: Обработка выбора уровня
- **`process_start_tasks`**: Обработка кнопки "Начать"
- **`process_continue_tasks`**: Обработка кнопки "Продолжить"

### 2. Tasks Handler (`bot/handlers/tasks.py`)

#### Команда `/task`

**Проверки:**
1. Проверка регистрации пользователя
2. Проверка дневного лимита (3 задания)
3. Получение задания из Notion

**Отправка задания:**
1. Формирование сообщения с заданием
2. Отправка медиа (если есть)
3. Отправка вопроса с клавиатурой (multiple choice) или запрос текста (open question)
4. Сохранение задания в FSM state

#### Обработка ответов

**Multiple Choice:**
- Извлечение ответа из callback_data
- Проверка правильности
- Сохранение в БД
- Удаление клавиатуры
- Отправка feedback (правильно/неправильно + объяснение)
- Переход к следующему заданию

**Open Question:**
- Получение текстового ответа
- Сохранение в user_answers для проверки преподавателем
- Сохранение в user_progress с is_correct=None
- Отправка подтверждения
- Переход к следующему заданию

#### Логика переходов

Функция `advance_to_next()` обрабатывает три типа переходов:

1. **next_task**: Следующее задание в текущем дне
   - Пауза 1 секунда
   - АВТОМАТИЧЕСКИ отправляет следующее задание

2. **next_day**: Следующий день (после 3-го задания)
   - Показывает статистику за день
   - Сообщает тип заданий на завтра
   - Сообщает "Увидимся завтра в 9:00"

3. **next_theme**: Новая тема (после 5-го дня)
   - Показывает итоговую статистику темы
   - Загружает название следующей темы
   - Сообщает о начале новой темы

### 3. Progress Handler (`bot/handlers/progress.py`)

#### Команда `/progress`

Показывает детальную статистику:
- Текущая позиция (тема, день, задание)
- Прогресс за сегодня
- Общая статистика (выполнено заданий, точность)
- Статистика по типам заданий

#### Команда `/my_answers`

Показывает открытые ответы пользователя:
- Непроверенные ответы (с деталями)
- Проверенные ответы
- Пустое состояние, если ответов нет

### 4. Help Handler (`bot/handlers/help_cmd.py`)

#### Команда `/help`

Справка по командам:
- Список всех команд
- Описание механики работы
- Контактная информация

#### Команда `/about`

Информация о боте:
- Описание возможностей
- Список уровней
- Версия и автор

#### Команда `/changelevel`

Смена уровня сложности:
1. Показывает предупреждение о сбросе прогресса
2. Запрашивает подтверждение
3. Показывает выбор нового уровня
4. Обновляет уровень в БД (сбрасывает прогресс)
5. Загружает первую тему нового уровня
6. Отправляет подтверждение

## 🧪 Тестирование

### Тестовый сценарий

1. **Регистрация:**
   - Отправить `/start`
   - Выбрать уровень
   - Нажать "Начать"

2. **Выполнение заданий:**
   - Отправить `/task`
   - Ответить на задание
   - Проверить автоматический переход

3. **Проверка прогресса:**
   - Отправить `/progress`
   - Проверить статистику

4. **Смена уровня:**
   - Отправить `/changelevel`
   - Подтвердить смену
   - Выбрать новый уровень

### Проверка дневного лимита

После выполнения 3-х заданий команда `/task` должна показать сообщение
о завершении дня и предложить вернуться завтра.

## 🐛 Известные ограничения

1. **FSM Storage**: Используется MemoryStorage
   - При перезапуске бота состояния теряются
   - Для production рекомендуется Redis

2. **Database**: Синхронный SQLite
   - Блокирует event loop
   - Для production рекомендуется PostgreSQL + asyncpg

3. **Rate Limiting**: Нет защиты от спама
   - Пользователь может отправлять много команд
   - Рекомендуется добавить rate limiter

## 📝 Примечания

### Важные детали реализации

1. **Автоматический переход**: После ответа на задание бот автоматически
   отправляет следующее (если это не последнее задание дня)

2. **Graceful shutdown**: Бот корректно обрабатывает Ctrl+C и завершается

3. **Error handling**: Все ошибки логируются, пользователю отправляются
   дружелюбные сообщения

4. **HTML разметка**: Все сообщения используют HTML для форматирования

5. **Middleware порядок**: LoggingMiddleware → StateLoggingMiddleware →
   ErrorHandlerMiddleware
